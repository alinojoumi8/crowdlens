## Resulting behavior

The default draft producer selects `section_summary_claim_ids`, not new summary prose. The server copies the selected ledger texts in order (with explicit analysis labels), validates claim links and size, and replaces only the unique selected-section occurrence in the frozen comparison summary. No IDs, duplicate/unknown IDs, competing summary contracts or unmapped targets block or remain unchanged for review as appropriate. Unrelated prefix/suffix characters remain protected. Existing strict legacy summary producers and sealed earlier proposals remain compatible. This prevents introducing a new proposition solely through model-authored summary prose; it does not certify the underlying ledger.

A malformed JSON completion can receive one syntax-correction request per phase. It uses the same workflow admission, usage accounting, remaining deadline and no-transport-retry settings. Both raw completions, hashes, parse failure and correction linkage are retained privately. Truncated raw completions, unrelated contract errors, transport errors and second failures do not trigger another correction. Every corrected response still passes all source, claim, scope and audit guards. The default collector cap remains 12; the explicitly frozen v6 protocol permits up to 24 requests including corrections.

New audits return explicit claim, paragraph, summary-edit and original-document judgments. Every expected claim/index/document must be covered exactly once. Only supported target judgments and complete document coverage pass; negative, ambiguous, unverified, omitted, missing or malformed judgments block. Summary consistency remains mandatory. A dedicated summary review contract identifies selected-section text, excluding protected unrelated context; unmapped summaries remain subject to contradiction review. Findings are derived from negative outcomes, rather than mixing successful checks into an error list. AI judgments remain fallible opinions.

Independent review caught a compatibility fallback that could ignore explicit negative target/document judgments when the protocol marker was absent. Final generation now requires `target_reviews_v1`; mixed contracts always block. Clean legacy audit helper compatibility is retained for separately scoped older uses, never as admission for fresh proposals. Both bypasses have regressions. The final independent provider-free review found no remaining blocker in the narrow fix.
