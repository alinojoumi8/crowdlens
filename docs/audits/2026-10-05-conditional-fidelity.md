# Conditional-offer correction

Detected English conditional offers (could/may/might with if/unless/provided/providing in the stored source excerpt) now require exact complete source sentences, wholly present in the retrieved window. Source sentence boundaries are checked against the excerpt, preventing a clipped retrieval window from dropping a trailing condition. Every claim citing such an excerpt is conservatively extractive. Analysis derived from these claims, including transitive premises, is blocked. Linked paragraphs must copy one claim exactly. Default summaries already copy ledger text. Generation and revision acceptance both enforce the checks under `evidence-draft-v6-conditional-extract`; earlier policies retain their scoped-summary acceptance checks.

This is a bounded English extraction rule, not general semantic verification. It can block faithful paraphrases and unrelated statements from the same excerpt. Sentence punctuation and stored chunk boundaries limit coverage; other conditional formulations still require independent review. Explicit only-when restrictions are not converted into offers.

Seven fail-first regressions reproduced the original weakness. The final suite passes 662 backend, 12 Node and 54 component tests (728 total), plus the production build. Independent review found the clipped-window loophole, now covered by two additional regressions.

Fresh frozen v7 contains two fictional cases, one attempt each, with three MiniMax-M3 requests. Thus these are conservative exact-wording false positives, not demonstrations of preventing semantic strengthening. They establish admission behavior, not generation quality or release readiness.
