# Conditional-source completion

The server now materializes one complete stored excerpt for each detected conditional source in the scoped retrieval packet. It reserves ledger IDs for those excerpts and lets the model plan only from the remaining source windows. Guarded claims cannot be duplicated by the planner or used for derived analysis. Valid single-claim guarded paragraphs use exact canonical ledger text; default summary sentences come from the ledger. No semantic repair requests or fuzzy paraphrase matching are used. Raw provider responses and server rendering provenance remain separate.

Whole excerpts avoid punctuation guesses such as splitting at Dr. and dropping preceding negation. A guarded excerpt must fit entirely inside the retrieved window and the 4000-character limit; incomplete excerpts block. Five guarded excerpts can fill a five-claim capacity when no ordinary source needs a planning slot. Scope/hash checks, paragraph contracts, full ledger coverage and complete explicit model audit remain mandatory. Rendered paragraphs are retained even when summary validation blocks, and exports identify the server origin.

Policies v7/v8 seal extract provenance and make it immutable after generation; acceptance rebuilds the frozen extraction contract, re-resolves IDs and rechecks paragraph/summary scope. Older-policy digest calculations remain unchanged. Coverage is conservative: detected English forms and stored chunk boundaries, not general entailment or source-truth certification.
